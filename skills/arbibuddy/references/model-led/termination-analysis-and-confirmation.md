# 解除分析与轻量高风险确认

本参考规定解除/终止事实的模型主导路由，以及在计划实施解除或其他不可逆动作前如何取得一次实质知情选择。它与[权益扫描、最终补充与统一确认](../rights-scan-and-unified-confirmation.md)分工：普通统一确认固定当前分析范围；本参考只处理新的高风险动作确认。

## 责任边界

模型负责识别解除主体、理由、日期、程序和送达事实，区分历史索赔与计划动作，解释风险、影响范围和替代方案，并用自然语言理解用户选择。模型不得把“被辞退”“离职”这类概括词直接改写成某一条解除路径。

模型只在需要确定性持久化时读取当前案情档案并使用 `CaseArchive.create`、`read`、`commit`。档案提交器只做 Markdown 原子写入、revision 冲突和引用完整性检查，不判断解除是否成立，不判断用户是否“应该”作出选择，也不发起下一问题。

不得新增解除分析脚本、分析器选择器、全局阶段机、确认卡、gate JSON、旧信封、逐轮 JSON、重试轮次或 Presenter。解除判断、方案比较、风险沟通和用户可见表达留在模型与本参考中。

## 三类解除事实路由

模型先询问或整理当前目标，再按以下事实路由；路由是分析路径，不是法律结论：

关键事实不足时只保留必要即时风险提示和一个问题；在事实尚不足以区分解除主体、理由、日期、程序或送达时，延后完整高风险说明、动态核验和确认，直到事实与用户目标足够。

| 事实情形 | 模型动作 | 是否需要新的高风险动作确认 |
| --- | --- | --- |
| 仅分析历史解除索赔 | 把已经发生的解除作为待分析事实，分析主张、证据、时效、金额和主位/备选方案 | 否。没有新的发送、解除或权利放弃动作，不得强迫确认不存在的动作 |
| 计划实施解除 | 先说明主体、理由、日期、程序、送达计划、风险、影响和替代方案；用户明确选择后才记录高风险确认 | 是。歧义或拒绝不得视为确认 |
| 已发送但送达事实待确认 | 先核对通知内容、发送时间和送达事实，再核对收件地址/账号、签收或接收记录和生效主张，决定属于历史索赔还是仍有后续动作 | 先核对事实；在事实未清前不得取得或使用新的动作确认 |

已经发送且送达事实明确、当前目标只是历史索赔时，适用第一类；如果用户另有新的不可逆目标，重新解释该新目标，不把旧发送事实当成新确认。

历史事实分层记录“用户称已发送”“有客观到达记录”“生效时间有依据”“离职手续完成”，不以一个“已解除”概括词合并。核对通知原文、收件主体及地址/账号、邮寄签收/拒收或电子到达原始记录、最后工作日、离职证明及继续工作的相反材料。只有寄件截图或本人自述时，仍可在“据用户陈述”的前提下分析历史请求，但送达、生效日及解除效果保持待核，不写成外发文书的确定事实，也不另行生成通知或要求确认并不存在的新动作。相互矛盾的送达与继续工作材料按条件情景分析，先澄清最关键的一处冲突。

免于新的动作确认并不免于实体和程序审查：历史分析仍核对每项法定理由、通知与送达、可能的解除时间、工资及补偿、各请求的仲裁时效及可能的中断/中止事实；超过一年不能不调查中断/中止就自动否定。已有裁决、判决或调解书时核对当事人、具体请求和效力范围，不机械排除不同请求。确有新的解除或重大权利处分目标时，另按本参考说明并确认新动作。

解除的风险是可能形成难以回转的实质后果，不等于寄出通知就当然生效或一律不能撤回。对生效或撤回的判断，核对适用规则、通知原文及实际到达时间；缺少到达证据时保持条件化，也不承诺撤回必然有效。

## 高风险说明的最低内容

涉及欠薪、降薪与去留比较时，先按[工资参考中的应得工资口径](wage-analysis.md#经济补偿的应得工资口径)核对，不把低实发当作补偿基数必然降低的理由。

在请求用户对计划解除或其他重大权利放弃作选择前，模型必须以普通语言说明：

1. 解除主体、具体理由、拟发生日期/生效日期和当前程序步骤；
2. 解除通知内容、送达方式、送达不确定性和证据保全影响；
3. 时效、工资/补偿基数、工作年限、对方抗辩和有权机关最终认定的不确定性；
4. 对用户权利、劳动关系和后续索赔的主要影响；
5. 可行的替代方案，例如先催告履行、补强证据、保留历史索赔、暂缓解除或先咨询专业人士；
6. 本次只请求用户选择是否按已说明的范围继续；模型不自动发送，模型不自动提交、签署或上传，也不替用户作出解除决定。

模型仍只能给出“信息不足”“有一定支持”“倾向支持”“倾向不支持”等条件化判断。成立、不成立、事实不足或冲突应说明依据和缺口，不得承诺胜诉、确定违法或必然生效。

## 高风险确认的唯一档案接缝

确认不是新的工具协议或流程状态。模型先 `read` 当前档案得到 revision `r`，并确认事实、证据和法律来源引用仍适用。用户明确选择后，只通过一次 `CaseArchive.commit` 追加一条 `confirmation` 记录；记录绑定提交后的档案 revision `r+1`，不得另建 gate JSON、确认状态机或独立确认文件。

记录只保留完成后续窄门禁所必要的字段：

- `action_type`：动作类别；
- `action_scope`：本次选择覆盖的具体动作和范围；
- `risk_summary`：已向用户说明的主要风险与不确定性；
- `alternatives_presented`：已向用户说明的替代方案；
- `user_choice`：用户的自然语言明确选择摘要；
- `confirmed_at`：确认时间；
- `archive_revision`：提交成功后的档案 revision；
- `source_refs`：当前事实、证据和必要法律核验记录的引用。

`CaseArchive.commit` 只记录这些必要事实。它不解析“确认”一词，不替模型判断知情程度，不保存逐轮回答或内部状态。确认记录中的来源引用必须指向当前档案内仍存在的事实、证据、分析或法律核验记录；来源 URL 可访问本身不等于已经核验。

## 选择、失效与抑制

- **明确选择**：用户清楚表达同意按已说明的动作和范围继续，模型才提交确认；“我明确选择按这个范围继续”等同义自然语言均可理解。
- **拒绝**：用户说不同意、拒绝或要求暂缓时，不提交确认，只提供补充、保全证据或候选分析路径。
- **歧义**：大概、应该可以、再看看等回答不能晋升为确认；模型只澄清当前选择，不重复整套解释。
- **revision 不一致**：准备说明后档案发生事实、范围或来源变化时，旧选择不覆盖新 revision；模型先重新读取，说明受影响内容，未取得新选择前不提交确认。
- **来源过期或冲突**：必要法律来源超过复核日期、发生冲突或当前状态未核验时，模型先做动态核验；不能以旧来源或 URL 存在替代当前依据。
- **重复确认**：同一 `action_type`、`action_scope`、当前档案 revision 和来源引用已经有有效确认时，不重复询问或追加相同确认。发生实质变化时只重新解释并确认受影响范围。

普通统一确认与高风险确认边界唯一：普通确认不代表计划解除的实质知情选择；计划解除的高风险确认也不重新要求用户确认已经完成的普通分析范围。历史解除索赔不因普通分析而触发新的动作确认。

## 用户可见隔离与非目标

用户只看到事实摘要、风险、替代方案、当前选择问题和清楚的下一步，不看到 `record_id`、`CONF-*`、revision、JSON、档案路径、CLI、内部状态或诊断。模型不自动发送、提交或发布任何解除通知，不生成被迫解除通知书，不替用户决定解除。
