# 加班工资：模型主导领域参考

本文件是加班工资知识的唯一模型可读参考。模型依据案情档案、法律知识基线和必要的动态核验完成事实判断、法律适用、证据组织、方案比较和用户解释；计算器只执行模型已经明确选择的单位、期间、倍数、上限和已付金额。旧专项执行层、CLI、私有载荷和固定调用轨迹不是运行期入口。

## 能力边界

- 深度支持标准工时制下的工作日延长工时、休息日工作和法定休假日工作三类加班工资。
- 综合计算工时、不定时工作制、特殊岗位、审批/备案状态、跨地区工资支付口径和法定休假日安排变化，先做条件化分析并动态核验；不能把标准工时制公式直接套用。
- 打卡、排班或登录记录只证明可能的时间线索，不能单独证明全部时间均由用人单位安排并实际用于工作。
- 休息日已经安排并实际完成补休时，不能与“休息日未补休工资”重复请求；法定休假日工作不能用补休替代相应工资。
- 加班主张可以和欠薪、劳动关系、未签合同或解除主张共享事实和证据，但每张主张分析卡必须写清不同证明目的。

对应深度支持争议：加班工资；与劳动关系确认、工资分析、未签书面劳动合同二倍工资、未休年休假工资形成交叉分析。社保、公积金和复杂争议仍按分层路由处理。

## 触发、最低必要事实与停止条件

模型在用户提到超时工作、休息日工作、法定休假日工作、调休或加班费未付时触发本参考。最低必要事实至少包括：

1. 适用工时制度、岗位和批准/备案状态；
2. 用人单位安排、知悉或事后认可工作的事实；
3. 争议期间、工作日延长小时数、休息日工作天数、法定休假日工作天数；
4. 休息日补休安排和实际完成情况；
5. 工资基数、适用日/小时折算口径、已付加班工资；
6. 申请日期、程序阶段、履行地和可能影响时效或地方口径的事实。

工时制度、安排状态、工作量、工资基数或已付金额存在缺口时，停止穷尽追问，给出“信息不足”和一个最高价值补强动作；关键事实已经足以形成条件化判断时，不因非关键材料缺失而阻断。证据冲突时保留互斥情景，不把其中较高金额自动作为主位方案。

## 全国基线、上海增强与核验元数据

- 全国基线：`NAT-OVERTIME-001@1.0.0`，对应《劳动法》第三十六、三十八、四十一、四十四条及工资支付、工资折算和仲裁举证规则；生效基线自 1995-01-01 起，最后核验日期 2026-07-17，法源强度为法律、部门规章/规范文件和官方司法资料。完整来源登记见 [`references/legal/overtime-rules.v1.json`](../legal/overtime-rules.v1.json)。
- 核心数学口径：工作日延长工时、休息日未补休、法定休假日工作的模型选择倍数通常分别为 1.5、2、3；这是模型选择的法律输入，不由计算器根据名称推断。
- 上海增强：上海工资支付、节假日安排、特殊工时审批和受理/时效口径属于地区或时间敏感变量；模型在适用时记录上海官方来源、适用日期、访问日期和影响范围。上海资料不能改写为全国规则。
- 旧来源中 `SRC-NAT-WAGE-CONVERSION-2025`、地方节假日安排或特殊工时口径超过复核期、发生冲突或用户要求最新依据时，转入动态核验；法源登记的 URL 存在不等于本案已核验。

## 事实、证据与分析假设

档案中把用户说法标为“用户陈述”，由考勤、排班、审批、工作成果、聊天、工资条或银行流水初步支持的内容标为“证据支持事实”，为比较情景而暂用的推断标为“分析假设”。分析假设不能进入确认快照或未经确认的正式文书。

证据—证明目的矩阵至少覆盖：工时制度和审批、用人单位安排/知悉、工作时段与工作成果、休息日补休、法定休假日性质、工资基数与已付金额、申请日期和程序阶段。工资条不是唯一门槛；合同、流水、个税、工作群、排班和成果可以按不同证明目的共享。电子材料只保全本人有权访问的原始设备、完整上下文、账号和时间信息，不建议违法取证。

常见抗辩包括“自愿留下”“只是待命”“未经审批”“已经调休”“不属于本单位安排”“工时制度不同”或“已经支付”。模型把这些作为待核查事实和证据问题，不替对方承认抗辩成立。

按[最高人民法院司法解释（一）第四十二条及典型案例](https://www.court.gov.cn/zixun/xiangqing/319151.html)，劳动者主张加班先就加班事实承担举证责任；劳动者有证据证明单位掌握加班事实存在的证据而单位不提供的，由单位承担不利后果。考勤/登录记录支持时间线索，排班与任务沟通支持安排/知悉，工作成果支持实际工作，工资记录支持已付或未付，各自不能单独证明全部时数和倍数。单位拒交其掌握的记录时提示可能的不利后果，仍结合现有材料、争议时段与相反证据判断，不能自动采信劳动者申报的全部小时，也不能因劳动者未持有单位考勤而一概驳回。工时制度、法定节假日性质、补休和工资基数另行核对。

## 主张分析卡与方案比较

每类加班分别形成主张分析卡，至少记录成立事实、当前事实状态、事实/证据/假设引用、证据缺口、对方抗辩、初步判断、金额口径、时效/程序、风险和下一步。初步判断只使用“信息不足”“有一定支持”“倾向支持”“倾向不支持”。

存在不同工时制度、工作量或工资基数时，方案比较卡逐情景记录前提、证据、法源、程序、互斥关系和重复获偿风险：条件相当且合法的方案可以推荐对劳动者更有利的主位方案；依赖未核实安排、特殊工时或地方口径的高额方案只能作为条件情景；已补休的休息日、已支付的同一加班小时和已在其他主张中计入的同一金额不得再次合计。

## 金额与 amount.calculate

模型选择 `overtime_pay@1.0.0`，为每个独立工作日/休息日/法定休假日分项显式提供：`yuan_per_hour × hour` 或 `yuan_per_day × day`、模型选择的 `ratio` 倍数、已付 `yuan`、期间日期和可选 `yuan` 封顶。纯数学为：

```text
max(0, 基数 × 数量 × 倍数 − 已付金额)
```

跨月、跨年或不同工资基数必须拆成独立 `line_items`；各独立分项先用 Decimal 在最终展示点按人民币分 `ROUND_HALF_UP` 舍入，再以展示值汇总。互斥工时或证据情景使用 `mutually_exclusive`，不得隐式求和或自动选择最大值。缺少工作量、基数或已付金额时，模型继续输出占位/条件情景，不伪造精确总额；计算器不判断是否应当主张加班。

## 动态核验与降级

特殊工时制度、上海或其他地方工资/节假日口径、来源过期/冲突、时效争议、用户要求最新规则及依赖当前规则的高风险外发定稿触发官方动态核验。联网失败时仍可完成一般分析、公式展示、计算和候选草稿，记录最后基线和受影响变量；只有未核验规则会实质改变不可逆外发定稿时，才暂缓该定稿并建议专业复核。

## 交叉影响与重复获偿

- 工资分析提供的工资构成或工资基数可以被加班和年休假分别引用，但不同计算的证明目的、期间和已付项目必须分开。
- 劳动关系确认是加班和未签合同的共同前提之一；劳动关系卡不自动证明具体加班时数。
- 休息日补休、法定休假日补休和同一笔已付加班工资需要与加班分项对照，避免重复获偿。
- 年休假、其他带薪假或工资差额的同一支付记录不能仅因名称相近而重复计入；模型在方案比较卡中说明纳入或排除理由。

## 四类最小行为样本

| 样本 | 事实与模型结果边界 |
| --- | --- |
| 成立样本 | 标准工时、安排事实、工时/天数、基数和已付均有支持；分别计算三类加班，并列证据缺口与对方抗辩。 |
| 不成立样本 | 已完成休息日补休，或材料显示不属于用人单位安排且无反向证据；说明当前不支持该分项，不生成精确金额。 |
| 信息不足样本 | 工时制度、安排、数量或基数缺失；给出条件情景/占位公式和一个补证动作。 |
| 事实冲突样本 | 考勤、排班、聊天或工资记录互相冲突；按不同工时/支付输入分情景，`grand_total` 不自动生成。 |
