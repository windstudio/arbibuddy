# 模型主导产品验收

2026-10-01：依据用户对连续修复与复验的反馈，采用结果与后果分层验收。与 ADR-0008、ADR-0009 一致；模型保留表达、分析和编排空间，确定性工具保护文件、算术、身份和高后果边界。

## 判断顺序

先写明本次用户目标、平台、候选或可外发定稿，再核对实际结果。结论分为“接受”“有条件接受”“不接受”“证据不足”。候选准备与实施解除/外发分别评估；某个分支接受不等于版本已正式发布。

| 层次 | 判据与处理 |
| --- | --- |
| 阻断问题 | 用户需要的核心交付无法取得；文件损坏或身份混用；关键事实/金额/证据被编造并实质影响结果；擅自增加实质请求、放弃权利或实施外发；把候选冒充已核定稿。必须定位主责并处理。环境超时使本次目标未完成，记运行无结论，不直接定性 Skill 缺陷。 |
| 核心功能 | 能保存/恢复案情，围绕用户目标给出有用分析，事实不足时明确待核或合理降级，需要文书时交付真实可打开的文件，并说明候选状态及必要缺口。按语义和实际产物判断，不要求固定话术、卡序或轮次。 |
| 非阻断质量 | 未改变实质范围的保守候选选择、候选中明确待补且档案仍保留的已知值、摘要繁简、偶发重复确认、未产生不一致的内部只读调用差异。记录后果与改进，不因单项存在便否决所有已完成目标。重复确认若导致任务停滞，则按核心交付未完成处理。 |

“有条件接受”须写清适用范围、缺点及使用条件，例如只接受供人工核对的候选准备、正式外发前仍需核实要素；不是自动称为定稿或已发布。遗漏的严重程度由用途决定：工资基数遗漏导致错误测算或错误正式请求属于阻断；候选留占位、未计算错误金额且档案保存陈述，可作非阻断质量项。合理保守推断仍应如实标为模型拟稿安排，不能把它写成用户原话；仅记录措辞不准与实际越权分开计量。

## 与测试证据的关系

原始 CLI PASS/FAIL、Oracle missing、场景原话与摘要保留。严格 Scenario 结果检查该测试路径的约束；产品结论综合用户目标、实际交付和后果。两者并列，不把未发送某张事实卡等同于不可用，也不把产品有条件接受改写成 CLI PASS。

收尾时逐项核对事实卡实际保护什么：来源、范围或动作授权真正缺失时补问或保留待核；只是另一种自然答复已表达同一意思、或保守候选未扩大用户权利处分时，记录严格路径缺口而不强制补卡重跑。历史核心证据可在核对相关代码、路由和契约差异后复用，写明原版本与未覆盖的修改；正式发布身份门禁仍按发布规范执行。

固定话术或步骤只有保护实质边界时才作为阻断。附加状态测试未覆盖不否决此前已完成的候选交付；附加状态答复若虚称文件有效、忽略实质变更，则另行阻断该分支。来源、授权、算术与文件完整性的确定性门禁继续保留。正式发布仍按既有三端证据、安装身份及制品规则执行；本政策不代替发布工具或伪造门禁通过。

## 收敛方式

一次评审先归因、评估后果，再决定是否值得改 Skill。核心目标完成且只余非阻断项时，冻结版本，集中记录改进，不继续逐项升版重跑。相同语义偏差多轮出现时，检查要求是否必要、参考是否冲突或负担过重；有实质阻断再作合并修订，不层层追加禁令。

后续真实测试在运行前固定目的和范围，只补核心目标或关键风险的证据缺口。环境失败允许在环境可用时安排有限的新运行，原结果仍保留；不重复运行直到碰到通过，也不要求跨模型所有轨迹完全一致。少量定向样本仅证明观察到的分支，不据此声称成功率或100%可靠。
