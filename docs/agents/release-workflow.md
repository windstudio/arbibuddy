# Public release workflow

Use a clean, reviewed commit on `codex/source` as the source of every channel. Keep the public branch history continuous; never merge private development history, raw native sessions, personal case data or credentials. Regression inputs are synthetic; see `tests/fixtures/README.md`.

1. Fix VERSION and the complete source commit. Review all outgoing files. Run the affected layered tests according to [testing.md](testing.md), and record the limits of inherited native/model evidence.
2. Generate a new external directory with `python -m scripts.release.skills_distribution --source <source> --output <new-directory>`. The generated `main` has no root SKILL.md; its install entry is `skills/arbibuddy/SKILL.md`. Commit the generated bytes without line-ending conversion.
3. In isolated user homes and synthetic workspaces, verify real skills CLI discovery, Codex/Claude Code, project/global, copy/default installation and an actual previous-version upgrade. Record actual link/copy mode and new-process identity, archive, calculation and document checks. Ordinary install: `npx skills add windstudio/arbibuddy`.
4. Build and verify the WorkBuddy artifact with `scripts.platform_adapters.cli`, an explicitly prepared offline wheelhouse and the locked Python ABI. Never silently fetch missing build dependencies. Package structure and distribution channels are different; do not rename a generic SkillHub ZIP into a WorkBuddy ZIP.
5. Prepare sanitized release-manifest.json, release-gate.json, BUILD-AND-REPLACE.md and reproducible evidence outside the source. Run `scripts.release.cli` with explicit five-category evidence. This command only verifies evidence files and runtime identity; it does not run tests or publish.
6. Assemble the materials with `python -m scripts.release.materials build --source <source> --workbuddy <zip> --dependency-sources <reviewed-source-zip> --notices <notices> --evidence <public-evidence> --output <new-directory>`. The evidence directory may include additional reviewed dependency source archives. Verify the resulting materials with `python -m scripts.release.materials verify <zip>`. See [download layout](release-downloads.md).
7. Generate a SkillHub ZIP using `python -m scripts.release.materials skillhub --skill <generated>/skills/arbibuddy --output <new-zip>`. Its root directly contains SKILL.md, VERSION.txt, LICENSE.txt and the distribution marker. Check all members and the 200-file/10,000,000-byte limits; provide a manifest and copyable changelog. Upload and submission are manual user actions.
8. Stage final artifacts under `<project-root>/dist/<VERSION>/`, with full member digests and gate evidence. Never overwrite an existing version. Verify before and after copying; use an outer delivery manifest to bind the materials archive without a self-referential hash.
9. Recheck remote bases, then push source and generated main normally (prefer atomic push). Create a Draft Release with tag `v<VERSION>` explicitly targeting the public source commit. Verify its three attachments before publishing a stable release as Latest. Preserve old tags and assets.
10. Download all uploaded assets without authentication and verify names, sizes, SHA-256 and the materials inventory. Test installation and actual upgrade from the public repository. Report branch publication, Release publication, SkillHub package delivery, manual listing and native acceptance as separate states.

Version changes require regeneration of every affected identity and artifact. A previous native run can only be inherited where code and dependencies are unchanged; it is not a new-version native/model PASS. Source materials include project code, actual dependency sources and license texts, modifications, build/replacement instructions and sanitized evidence. Do not claim bit-for-bit rebuildability unless tested.
