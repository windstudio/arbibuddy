# WorkBuddy 使用与能力边界

当前支持平台为 Codex、Claude Code、WorkBuddy。WorkBuddy 使用上传ZIP方式导入完整Skill；导入后核对安装目录 VERSION，再在隔离工作区进行接续和文书复核。Skill调用、档案读取和真实交付应分别提供直接证据，客户端显示“已加载”不能证明模型已执行。

安装包包含相同核心白名单和便携身份标记；受管安装另有绑定回执与外部信任锚。身份或依赖不匹配时应重新导入正确包，不在案件回合修补安装树、联网安装依赖或手工删除案件文件。

文书使用 `scripts.documents.runtime_cli` 的render和只读view：模型提供完整正文，工具验证锁定字段、档案修订、文件结构与原子交付。candidate可带明确待补项，external_final须满足完整绑定与适用高风险确认。用户能取得文书和核验清单后，在Word/WPS检查内容与显示；机器文件校验不能代替这个确认。

恢复-only回合遵守Skill的读取后停止边界。平台memory注入与自动写入是宿主诊断问题，不作为案件事实来源，也不能据此改写案件档案。

实际能力不足时按 [平台能力边界](../../references/platform-capabilities.md) 说明限制并提供可保存内容；无联网不等于已核验新规。历史安装与兼容探测仅为 历史证据（原始报告私有保留，公开边界见 [验收摘要](../acceptance-summary.md)），不代表当前版本验收通过。
