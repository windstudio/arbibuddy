# 模型主导编排与最小工具边界

ArbiBuddy 由核心 Skill 引导模型完成案情采集、权益发现、法律分析、方案比较、用户沟通和文书正文生成，普通对话不再以 PublicRuntime `advance/status` 为必经入口。脚本只保留 Markdown 案情档案原子写入、确定性算术、DOCX 生成校验以及安装发布完整性；工具契约必须完整、自描述并一次返回可定位错误，不能因模型调用失败扩张为对话状态机。

## Considered Options

- **继续就地重构 PublicTurn v2**：拒绝。它会保留阶段、信封和结构性测试的历史耦合，并继续把 Agent 变成状态机的自然语言界面。
- **完整产品从零重写**：拒绝。专项分析知识、金额规则、文书模板、OOXML 检查和平台能力仍有独立复用价值，全部重建成本更高。
- **模型主导、选择性重写**：接受。重写编排内核，只复用符合新边界且重新验证成本更低的叶子能力。

## Consequences

- PublicTurn v2、v1/v2 公共信封、每轮 JSON、集中 capability referral 和依赖旧阶段轨迹的测试退出正常产品路径，不承担未发布兼容。
- Markdown 案情档案继续是唯一案件事实源；工具 JSON 仅瞬时使用，内部编号由最小档案提交器生成。
- 九项专项分析保留为模型能力，但其运行期分析服务只作为知识、公式和测试场景的迁移来源；提取完成后删除。模型选择法律计算口径，统一计算器只执行输入校验与确定性算术。
- 不使用运行期 Hook、轮次令牌或客户端业务副本。模型依 Skill 执行单问、权益扫描、确认和用户可见隔离。
- 基础全国法律在 Skill 发布时核验；地方、时间敏感和新近规则由模型使用 Agent 联网能力按需核验，不保留案件级受控下载状态机。
- 测试以完整业务结果、案情档案、金额可复算、文书质量和用户可见行为为主，不再把内部阶段轨迹当成产品正确性。
- 文书正文与高风险最终化的进一步边界见 ADR-0009。
