# 模型完整起草文书，确定性工具只负责交付与轻量最终化

## 背景

文书是 ArbiBuddy 的核心交付，但正文质量依赖对完整案情、主张策略和用户目标的理解。让程序拥有正文区块、法律叙事和高风险对话状态，会复制模型已经具备的能力，并持续扩大 LUI 状态机。另一方面，金额、主体、日期、版式、占位符、内部信息泄漏和 DOCX 结构需要确定性保障。

## 决策

- 模型依据核心 Skill、已确认的 `案情档案.md`、法律知识基线及必要动态核验起草完整文书正文。
- DOCX 工具接收单次瞬时结构化输入，只负责模板排版、章节顺序、锁定要素一致性、占位符和内部信息泄漏检查、DOCX/OOXML 校验、原子交付及独立内部核验清单；不补写或改写法律正文。
- 信息不足时允许生成明确标识的候选草稿。可外发定稿不得包含未决占位符。
- 高风险动作的后果、替代方案和不确定性由模型向用户解释；用户确认及关联风险写入唯一 Markdown 档案。
- 高风险最终化工具只检查对应确认记录、引用一致性和实质依赖的易变规则核验状态，不判断法律策略，不发起重试轮次，不维护独立 gate、ledger 或流程状态机。
- 用户提交或发送前仍应在 Word/WPS 中检查分页、金额和落款；该预览不替代确定性检查。

## 考虑过的方案

- **程序根据结构化区块生成正文**：拒绝。它把法律叙事和案件理解复制到模板及脚本，并迫使模型适配私有载荷。
- **模型直接生成 Word 且不校验**：拒绝。无法稳定保证锁定字段、文件结构和排版质量。
- **模型完整正文 + 窄 DOCX 工具 + 轻量最终化**：接受。模型保留智能，程序只保护确定性和高后果边界。

## 后果

- ADR-0003、ADR-0004 的统一生成和确定性检查目标继续保留，但正文所有权、状态名、schema 和发布阶段不再构成兼容要求；两项 ADR 由本 ADR 取代。
- ADR-0006 中结构化文书草稿和旧状态编排不恢复；有效的 Harness 优先原则继续适用。
- 八类文书必须分别证明内容完整、锁定字段一致、无内部泄漏、OOXML 有效和视觉排版可用。
- 文书工具契约必须一次完整公开字段、类型、必填条件、示例、错误位置和恢复方法，避免模型靠多轮报错猜测。

## 2026-09-29 候选稿新鲜度补充

候选稿允许在业务依赖未变化时跨档案修订版本复用。工具对整个当前业务章节和被引用下一步记录作确定性摘要核对，只排除未被引用的下一步备注及更新记账；新增业务记录即使没有直接绑定正文也会使旧稿失效。摘要保存在既有交付控制对象和机器清单，不保存第二份案情正文，不让模型凭“无关更新”标志绕过核对。

原始生成 revision、文件和清单摘要保持不变，只读 view 分别报告原版本、当前版本及核对结果。旧清单没有依赖证明时保留严格版本检查；external final 继续严格绑定当前版本。记录分类、事实来源、法律判断、候选请求范围和单问选择仍属于模型职责。
