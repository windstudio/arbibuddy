# 案情简报

用户要见律师、希望把案情整理给首次接触本案的律师时，使用此路径；律师在调解、仲裁或诉讼中途介入同样适用。一次交付一份可编辑的 Word，当事人可在同一份文档中审阅、编辑并自行转交，原始证据由其选择另附。

## 起草与完成条件

1. 按 Skill 案件入口绑定并读取当前工作区、当前案件的案情档案；已有成功读取可复用。咨询目的明确即可整理；目的不清时只追问这一个问题并等待答复。权益扫描、最终补充、摘要确认、证件联系方式、材料齐全和金额核定均非起草前提。
2. [核对来源](#来源核对)后起草正文。必要的新事实或来源整理合批提交档案，使用成功回执的最终 revision。简报以档案为事实来源，重组正文不改变档案中的事实、诉求或材料状态。
3. 按[文书 transport](../document-render.md#模型唯一入口与客户端-transport)调用既有 delivery-set → render → view → 一次 present_files。类型为 `lawyer_case_brief`，别名为 `lawyer-case-brief`，首次生成和后续改稿的 delivery-set 与 render 均使用 `external_final`，并传 `confirmation_refs: []`、`authority_refs: []`。这表示当事人可自行转交的整理稿。把未核实的事实和材料照实保留在正文。首次展示完成本次请求，无需再回复“确认定稿”或领取第二份文件。只有 Word 进入展示列表，内部核验清单仍由工具保存和校验。

## 来源核对

提交档案前，把材料名称和状态分别对回当事人原话或实际收到的内容。仅将明确提及或实际收到的材料写入证据记录及材料表。“材料另附”未指明名称时，只在编制说明交代。仅陈述付款或口头通知经过时，在事实中记录经过，相关凭证、录音或书面记录是否存在留为未知。对于已提及的材料，按实际接收与阅览状态写明“本次未收到、未阅”等限定，向律师或机构的提供状态按各自来源记录。只收到抄录时，在对应章节写“据当事人抄录，……；原件未收到、未阅”，开庭日期与裁决认定同样处理。

程序状态逐项取自来源。“计划申请”保留为计划，是否实际提交及后续进展未核实；只有当事人或材料明确说明未收到通知，才写“尚未收到”，否则保留通知状态未知。只知道口头原话大意时用转述；法律判断写成咨询问题。

先核对是否有来源明确界定案情覆盖日期。新增来源时，在同一条事实记录写 `案情信息截至：具体日期` 并保留原话或所引材料。已有记录明确说明同一信息范围时，可直接绑定原记录。若无此来源，首页写 `案情信息截至：不详`，该项无需日期绑定。会话日期、生成日期和个别事件日期各有用途。

沿用[事实分层](../model-led-case-archive.md#事实分层)。从事实、请求、证据及已记录的分析、风险和待办提取信息，按原来源确定信息等级。分析项可提示待明确事项或咨询问题，事实依据仍需回到原陈述或材料。

## 正文

工具写入正式标题「案情简报」及副标题「供律师咨询参考」。首区块 `案情信息` 各写一行 `当事人：…`、`案件类型：劳动争议…`、`案情信息截至：…`。默认使用档案中的当事人姓名或已确认的称谓，按用户要求处理隐名；案件类型用中性表述。按档案明确的信息覆盖范围写截止日期，未知写“不详”，后续进展未核实时注明。采用第三人称，保留所需公司全称和人员角色，默认省略证件号、住址、卡号、私人手机号及内部记录标识。

先按八模块归类，再确定章节。多项相互独立的争议同时涉及有时间锚点的跨期事件或已知程序安排时，采用按下表顺序展开的完整结构。各项争议设二级标题，基本案情下设「关键事件时间线」。主体关系或证据冲突复杂时也可展开。少量关联争议、时间信息稀疏、程序仅知已申请时采用精简结构。信息截止日放在页首。

| 模块 | 内容归属 |
| --- | --- |
| 案件概要 | 一至两段概括核心争议、劳动关系现状与当前阶段。概要直接写出已知开庭、送达等重要安排的日期和来源，例如“据当事人转述，通知原定某日开庭，实际进展未核实”。日期已过仍照录通知日期，进展章节再展开。 |
| 基本案情 | 归集共同背景与劳动条件。用档案支持的「劳动合同签订单位」「实际用工主体」「工资支付单位」等角色标注主体。关键事件多且顺序可追溯时设置「关键事件时间线」，把各来源的事件按发生日期从早到晚合排；期间按起点排序，日期不详时保留已知的相对次序。 |
| 主要争议事项 | 逐项呈现实争事项及当事人明确请律师评估的已发生事项，例如未签书面合同期间。完整结构中分别设中性二级标题，单项可用自然段。并列当事人、对方和材料的不同说法及重要不利事实，保留原话、日期或金额的不确定性及意见未知状态。 |
| 争议处理进展 | 按实际情况记录协商、投诉、调解、仲裁、诉讼或执行的机构、日期和通知。已正式提出的请求及金额、处理结果及裁决金额分别写入本节，已有结果时仍保留原请求。区分计划、申请、受理、开庭、裁决、送达及生效。根据档案注明已知程序时间和风险，期限或救济路径待判断时将其写成咨询问题。 |
| 当事人诉求 | 记录当事人明确的目标、目前拟主张的事项及已知金额；只想咨询、尚未决定行动时写明。完整结构单列已知目标，即使概要已提及。潜在权益和已在程序中提出的请求分别归入咨询议题和程序进展。 |
| 证据及材料情况 | 逐项列材料、关联争议和实际状态，可用表格。区分已提供且已阅、部分已阅、未阅、当事人提及但未提供、称无法取得及状态未知。已阅仅支持所读范围，材料存在、提供或阅读均不足以认定真实性或待证事实。仅列档案中的真实材料和线索，不列推导出的补证清单或采信结论。 |
| 尚待明确的事项 | 用“尚不明确”“未提供”“记载不一致”等客观状态集中呈现重要缺口和矛盾。工资期间只有月份时，明写“该笔工资所属年份不详”。申请书请求额与当前估算不同时，明写差异原因是否已知。事实所在章节仍保留必要的限定。 |
| 拟与律师讨论的问题 | 优先转述当事人的咨询目标，用开放、中性的疑问句。只有一个咨询目标时优先留一条，将同一请求的材料是否充分、还缺什么合问。按案情补充的关联议题可标作「供讨论」，超出原咨询范围的议题须已获确认才可纳入。只提出供律师作专业判断的问题。事实核对事项归入「尚待明确的事项」，咨询问题后不附请律师核对、调查、补证或办理的要求。胜诉预测和办案策略留给律师。 |

争议集中、信息较少时用精简结构，事件先后用一段正文交代。前四模块按有效内容保留，证据和缺口都具备时合并为「证据及待明确事项」，诉求和咨询问题都具备时合并为「当事人诉求及咨询问题」。合并后分别保留两个原模块的二级标题；只有一个模块有内容时可单列该模块。忽略无实质内容的模块，重要未知仍应保留。精简通常一至两页，完整通常二至四页，关键信息充分优先。编号与自然分页由工具处理。

关键说法就近注明当事人陈述或材料名称及可辨认来源。按来源原有精度写日期；仅知月份时保留月份，原话只记得大意时用转述。估算金额在争议事项写一次，正式请求及裁决金额在程序进展写一次，分别注明事项、期间、出处和性质。待明确事项指出差异及缺口，概要和咨询问题用“现估与已提交请求的差异”一类短语交叉引用。重要庭期仍在概要显著位置写明。

末区块 `编制说明` 用两句交代实际来源、核验范围和用途。仅有口述或抄录时可写“本简报根据当事人陈述及其抄录内容整理，所涉事实和材料未经独立核验。供律师阅案及沟通参考。”按实际来源保留“抄录内容”，如已阅部分材料则写明所阅范围。详细材料状态集中在前文材料表。

调用 render 前逐行核对材料名称、状态与程序进展的原始来源，复核时间线相邻事件的日期顺序。再检查矛盾和不利事实、金额口径及请求归属、章节裁剪和隐私。待明确事项用状态描述，咨询问题保留独立专业判断空间。

## 来源绑定

用 `describe --operation render --document-type lawyer_case_brief` 获取正文区块、二级标题和表格语法及可执行虚构示例。沿用[锁定要素契约](../document-render.md#锁定要素与档案绑定)：

- 标题 `案情简报` 以 `document_heading` 绑定档案中的排版准备信息。主体用“角色：完整名称”绑定档案中的身份字段，角色沿用档案来源。匿名时用已确认的称谓，保留档案中的姓名记录。
- 全部完整日期以 `date` 绑定实际来源，包括案情信息截至日期和开庭日期；截至范围来源不足时直接说明不详。没有完整日期不要求补猜或添加落款。
- 引述估计、材料数额、已经提出请求使用 `fact_amount`，仅此类型允许引用原 `F-*`、`E-*`、`CL-*`，任意简报章节均可使用。数值仍须被引用记录支持并逐处填写 `occurrences`，来源包含事项、期间和数额含义；原记录以阿拉伯数字“万元/亿元”记载时，正文按同一数额规范为元，工具核对单位等值，不改写原记录或补做请求金额计算。新计算结果继续用 `amount` 绑定真实成功的 `CAL-*`。不把内部编号写入正文。
- 用 `evidence` 等已有绑定保留关键材料来源，绑定值须同时见于所引记录和正文。档案称谓较简短时沿用已有名称，阅览范围按来源记录。允许引用包含冲突的记录，以便相邻呈现双方口径；分析假设仍不能当作事实锁定。工具不判断真实性或律师策略，模型保留分歧和待核问题。

## 修改

修改已交付简报先按[改稿指南](../document-edit.md)取得可信原稿。涉及隐名或单项纠正时，用 `edit-context` 返回的可见文字逐处替换指定原值，保留其余文字、顺序、标点和已用编号。用户要求把“某姓名”替换为“当事人”时，页首写“当事人：当事人”，表格与正文也使用同一个目标词。随请求提交全部绑定，保留未受影响的值和来源。核对编制说明及其他段落仍与原稿一致。隐名沿用原档案 revision。核实后用 `replace` 更新事实时，`content_markdown` 只保留有效的新值及核实来源，原值和更正经过放在 `reason`，再按新 revision 重交付。旧版更新或不能验证原稿时，沿用改稿指南的重建规则。
