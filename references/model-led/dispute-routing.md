# 争议路由：模型主导领域参考

本文件是 04 号工单中争议路由知识的唯一模型可读参考。它指导模型把社保、公积金和复杂争议分成可理解的路径/风险卡，不是一个由脚本决定路由的专项分析执行器。

## 路由状态与边界

| 争议类型 | 默认路径/状态 | 关键限制 |
| --- | --- | --- |
| 社会保险缴费 | `administrative_handling` | 优先识别社保经办、征缴、劳动保障监察或税务等行政处理/投诉核查；不得默认包装为劳动仲裁请求 |
| 住房公积金缴费 | `complaint_verification` | 优先识别住房公积金管理中心投诉、调查或责令缴存路径；不得把补缴路径直接当作金额主张 |
| 社保待遇损失、不能补办、解除或赔偿交叉事项 | `conditional_cross_route` | 只有在损失、补办可能性、程序阶段和请求基础核实后，才说明仲裁/诉讼交叉；必要时建议专业复核 |
| 工伤、职业病、竞业限制、劳务派遣、股权激励、涉外用工 | `professional_review` | 只做信息采集、风险识别、可靠来源核验和专业复核建议，不生成与深度争议相同的金额或正式文书 |
| 来源过期、冲突或联网受阻 | `pending_verification` | 说明未确认变量和影响，暂缓确定具体机关或程序；一般分析和候选准备可以继续 |

模型负责依据事实选择路径，不能让用户或客户端选择一个分析器来替代判断。路径卡至少写明争议类型、状态、地区、程序阶段、请求类型、已确认事实、最少必要事实、风险标签、紧急提示、适用条件、待核验项、官方来源、专业复核建议和下一步。

## 事实、证据与交叉影响

路径卡只能引用档案中的用户陈述或证据支持事实，并明确分析假设。一个工资流水、缴费记录或解除通知可以和劳动关系、工资、解除等卡共享多个证明目的，但必须在每张卡中说明具体证明目的；不得因共享证据而自动推定其他事实成立。

社保或公积金的行政路径与工资、解除、待遇损失等请求可能并存，也可能互斥或发生重复获偿风险。模型先说明请求对象和程序差异，再比较是否需要并行处理；计算器不读取路由卡、不决定程序、不生成金额。路径卡本身不写金额、胜率、最优方案或确定违法结论。

## 规则与核验元数据

- 全国基线：`NAT-DISPUTE-ROUTING-001@1.0.0`，适用范围为全国缴费处理和复杂争议分层，生效日 2026-07-18、失效日未登记，规则整体最后核验日 2026-07-18，复核日 2026-10-18；制定/发布机关包括全国人大常委会、国务院、最高人民法院及国家部委；法源强度按社会保险法、住房公积金管理条例、工伤/职业病/派遣规范和最高人民法院司法解释或官方案例分别记录。官方链接：<https://shanxi.chinatax.gov.cn/web/detail/sx-11400-545-1784612>、<https://www.shanghai.gov.cn/nw4544/20200905/0001-4544_302.html>、<https://www.court.gov.cn/zixun/xiangqing/472691.html>。
- 上海增强：`SRC-SH-SOCIAL-ROUTE` 与 `SRC-SH-HOUSING-COMPLAINT` 分别记录社保缴费争议受理和公积金行政投诉口径；两条登记来源的有限命题均于 2026-09-23 核对，下一复核日均为 2026-10-18。上海人社 2025-03-11 咨询答复称本市仲裁机构自 2014 年 7 月起不再受理社保缴费争议，提示监察投诉或请求社保经办机构处理；它不是新增法定程序，也不覆盖社保待遇损失等交叉请求。官方链接：<https://rsj.sh.gov.cn/tfkcx_17604/20250312/t0035_1431158.html>、<https://www.shzfgjj.cn/html/newxxgk/zcwj/gfxwj/209543.html>。地区、程序阶段、请求类型和现行口径变化时必须动态核验，不把上海做法复制为全国规则。
- 历史回归：社保与公积金分别路由；待遇损失进入条件交叉；六类复杂争议保持专业复核；来源过期/冲突统一降级；旧 ROUTE 编号重排只属于 obsolete 门禁。具体场景见迁移表。

## 样本行为

| 样本 | 模型应表达的边界 |
| --- | --- |
| 成立样本 | 已确认欠缴事实和地区口径时，给出行政处理候选路径、待核验机关和保全材料 |
| 不成立样本 | 材料显示已正常缴纳或请求并非缴费事项时，不强行生成社保/公积金路由，说明当前不支持该路径 |
| 信息不足样本 | 地区、程序阶段、请求类型或当前口径缺失时，使用 `pending_verification` 并只追问一个最高价值问题 |
| 事实冲突样本 | 缴费记录与用户陈述或待遇损失材料冲突时，保留冲突和条件交叉路径，不把任一方直接写成最终事实 |

复杂争议始终保持分层支持。动态核验失败只改变受影响路径的确定程度，不应把整个案件、工资计算或普通候选草稿变成系统失败。

## 公共接缝

模型将路径/风险卡作为自然语言分析结果组织，并通过 `CaseArchive.commit` 写入 `analysis` 或 `next_step` 记录。参考资料和官方来源登记提供法源线索；模型负责判断适用性、冲突和解释。不得使用旧 `dispute-routing` CLI 的绝对路径、私有载荷或固定 ID 顺序，也不把 `ROUTE-NNN` 当作用户需要理解的术语。
