# 工资、奖金与工资差额：模型主导领域参考

本文件是 04 号工单中工资分析知识的唯一模型可读参考（能力标识：`wage-analysis`）。模型负责选择主张、法律口径、期间、工资基数、倍数、上限、情景、证据解释和主位/稳健备选；`amount.calculate` 只执行已显式选择的数学。

金额接缝只使用 `scripts.amount_calculator.public.AmountCalculator.calculate` 的 `amount.calculate-v1` 公共契约，并在成功后由模型通过 `CaseArchive.commit` 写回必要结果。

## 地区门禁

适用地区未由当前用户或当前案情档案确认时，分析、风险、下一步和 `CaseArchive.commit` 文本只写“地方规则待核验”；本参考中的具体地区、来源名称、网址和地方示例是知识参考，不是当前案件事实，不得作为未经确认的案件适用地区或地方规则复制到档案。只有用户明确确认地区后，才可记录该地区并按分层法律核验处理相应地方规则。

## 支持范围与事实状态

可分析拖欠工资、工资差额、销售提成、项目奖金、绩效奖金、年终奖金和十三薪等交叉主张。每项主张都要区分：

- `complete`：关键事实、证据角色、条件和口径已足以形成精确输入；
- `pending`：关键输入或证明目的缺失，使用条件情景或占位公式；
- `conflict`：事实、证据、支付条件或收入性质互相冲突，使用情景或占位，不生成伪精确合计。

主张分析卡至少写明成立事实、事实状态、已确认事实与分析假设、`evidence_roles` 证据角色、证据—证明目的矩阵、可替代证据、证据缺口、对方可能抗辩、初步判断、金额口径、风险和下一步。经营困难、资金困难或“非恶意拖欠”只作为待核查抗辩，不能被模型替用人单位确认，也不能消灭劳动者的请求。

单位提出经营困难、资金紧张、非恶意拖欠、延期发薪或降薪时，分别核对欠付期间与应发/实发、抗辩提出时间及财务依据、延期方案与实际付款、工会/职工代表协商及全员告知、劳动者同意或异议的具体范围和催告。知晓经营状况、个人口头同意、沉默、继续工作或领取部分工资，都不能自动证明有效集体协商或放弃工资；如确曾同意则如实记录，不引导隐瞒。合法取得的同期付款、经营、招聘线索仅用于核查，不单凭对外付款推断必有支付能力；不替对方确认“恶意”。欠薪本金、降薪变更的效力与可能的被迫解除理由各自分析，不共享一个抗辩结论。本节为经营困难抗辩的现行模型口径。

工资条不是唯一证据门槛。合同、录用通知、调薪记录、银行流水、个税/社保记录、考勤、工资沟通和制度文件可以按证明目的互相补充；同一证据可以在工资、劳动关系和解除卡中共享，但档案只保存一份 `E-*` 记录，并在各卡中说明不同证明目的。

## 经济补偿的应得工资口径

经济补偿月工资按解除或终止前十二个月的应得工资平均数确定，不满十二个月按实际工作月数计算，工资构成包括计时/计件工资、奖金、津贴和补贴等货币性收入，并另核对适用上限。银行到账额用于核对实际支付，不直接代替应得工资；欠薪、领取部分生活费或继续工作本身不证明有效降薪，也不自动降低补偿基数。真正的工资标准变更、待岗停工及其适用规则须依据具体事实另行判断。

例如正常提供劳动、约定月薪15000元但当月只收到3000元，不能仅凭到账额把该月应得工资认定为3000元；约定月薪也不直接等于已核实的十二个月平均基数。若存在有效工资变更，则按变更效力、时间及各月应得工资核算；效力有争议时保留条件情景。工资标准、应得构成、实付、欠付差额及补偿平均基数分别记录，判断“现在离开还是继续工作”时不以低到账额必然压低补偿为依据。

依据：《劳动合同法实施条例》第二十七条，[人社部关于经济补偿标准的说明](https://chinajob.mohrss.gov.cn/c/2024-08-09/413251.shtml)，2026-10-02核对。模型选择法律口径，计算器仅执行明确的输入和公式。

## 收入性质与条件

- 拖欠工资、单方降薪和法定津贴分别记录应发标准、实际支付、期间、扣款/调薪依据和差额。沉默、继续工作或领取较低工资不自动等于明确同意降薪。
- 销售提成要核对签约、回款、验收、结算、退单或冲销等触发条件；业绩发生不自动等于提成到期。
- 项目奖金要分别核对项目完成、验收、分配规则、个人贡献和审批状态；未验收或审批被拒时不得靠自由文本绕过条件。
- 绩效奖金要核对制度制定/公示、考核结果、申诉调整和裁量条款；制度未公示或考核未通过时保持 pending/conflict。
- 年终奖金与十三薪分别记录性质、约定、归属期间、在职/绩效条件、历史惯例和已付金额，不因名称相同而合并。同一经济收入用同一收入项目引用，不能在多个主张中重复请求或重复合计。

## 方案比较与金额接缝

存在多个合法基数、期间、收入性质或互斥救济时，模型先建立方案比较卡，逐项记录法律前提、事实/证据引用、时效和程序、冲突、重复获偿风险、待补证据、适用条件和推荐状态：

- `primary`：法律基础、事实和证据支持相当时，对劳动者更有利的合法主位方案；
- `fallback`：条件更稳健或待补证据较少的合法备选；
- `not_recommended`：法律基础不足、事实已否定、时效/程序不允许、互斥或可能重复获偿的方案。

高额但依赖未确认事实、地方口径或争议性收入性质的方案只能保持条件化情景。计算器不得读取方案比较、自动选择最大金额或输出“最优/胜诉金额”；互斥情景不得放在同一合计中。

模型需要精确金额时调用 `amount.calculate`，请求必须显式携带 `formula_id`、`formula_version`、`legal_basis_summary`、`source_refs`、`scenarios`、单位输入、期间数学约定和 `rounding_policy`。月、日、小时等量纲必须匹配；连续公式保留未舍入中间值，每个独立分项在最终展示点使用 Decimal/ROUND_HALF_UP 舍入后再汇总。工具成功后，模型通过 `CaseArchive.commit` 把必要的口径、假设、公式、来源、分项、舍入规则和合计写入档案；工具不直接写案件文件。

## 四类行为样本

| 样本 | 模型结果 |
| --- | --- |
| 成立样本 | 约定工资、实际支付、期间和证明目的均有支持，选择合法 `primary`，调用计算器生成可复算精确结果 |
| 不成立样本 | 事实已显示支付条件未成就、请求超出程序或与已选救济重复，标记 `not_recommended` 并解释原因，不让计算器替代法律判断 |
| 信息不足样本 | 缺少期间、基数、支付条件或关键证据，使用 `pending` 与 placeholder/scenario，列出一个可执行补强动作 |
| 事实冲突样本 | 合同、流水、制度或双方陈述冲突，保留 `conflict`，分别计算明确情景或暂不合计，不把更高数字自动当主位 |

## 交叉主张与高风险边界

十三薪可以作为独立欠付本金，也可能在满足性质、归属期间、证据和适用救济条件时影响特定工资基数；两种法律作用必须分开引用，不能重复获偿。工资与劳动关系、解除、社会保险路径共享事实时，模型要说明共享证明目的和不共享的缺口。

在职欠薪适用《劳动争议调解仲裁法》第二十七条的特别规则：劳动关系存续期间因拖欠劳动报酬发生争议，不受通常一年仲裁时效期间限制；劳动关系终止后应自终止之日起一年内提出。具体欠薪月份用于确定请求期间、金额和证据对应，不得仅因具体月份待核实，就把在职欠薪表述为仲裁时效起算不明。二倍工资、未休年休假工资、经济补偿或赔偿金等其他请求不能自动套用这一特别规则，应分别判断请求性质和时效。

在职欠薪的特别时效不表示全部请求都可以等待，也不消除证据灭失或单位资产变化的风险；仍提示及时固定证据和逐项核对时效，不据此建议用户延后处理。

本参考不规定固定用户措辞、分析顺序或旧 CLI payload。普通分析和候选金额可以在动态核验暂时不可用时继续；如果未核验的易变规则会实质改变不可逆外发定稿，模型才暂缓该定稿并说明限制。
